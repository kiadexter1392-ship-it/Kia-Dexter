# آکادمی ارسلان — پنل شاگرد، مربی و مدیریت

وب‌اپ فارسی و راست‌به‌چپ با Node.js 22.5+ و SQLite داخلی؛ اجرای سرور نیازمند نصب وابستگی نیست. رابط وب Vanilla JS است. کد `mobile/` پروژهٔ جداگانهٔ موبایل است و این امکانات وب به‌طور خودکار به APK تبدیل نمی‌شوند.

## اجرا و مسیرها

```sh
npm start
```

| بخش | مسیر محلی |
|---|---|
| شاگردان | `http://localhost:8080/` |
| مربی | `http://localhost:4174/` |
| خدمات شاگرد در دامنهٔ مربی | `/member/academy` |
| خدمات مربی | `/academy` روی ۴۱۷۴ یا `/coach/academy` روی ۸۰۸۰ |
| مدیریت مستقل | `/admin` روی ۸۰۸۰ یا ۴۱۷۴ |

پورت ۴۱۷۳ بک‌اند داخلی شاگردان است. URL مرورگر در پیش‌نمایش یا Railway نباید `localhost` یا شمارهٔ پورت داخلی داشته باشد. پورت‌ها با `PORT`، `COACH_PORT` و `MEMBER_PORT` قابل تنظیم و باید متفاوت باشند.

## ایجاد اولین مدیر — بدون حساب یا آمار نمونه

در اجرای عادی **هیچ مربی، شاگرد، نمره، افتخار، اعلان یا حساب پیش‌فرضی ساخته نمی‌شود**. روی سرور با مسیر دیتابیس مشترک، متغیرهای زیر را از طریق محیط امن تنظیم کنید:

- `ACCOUNT_USERNAME`: نام کاربری مدیر؛ انگلیسی، حداقل ۳ کاراکتر
- `ACCOUNT_NAME`: نام واقعی مدیر
- `ACCOUNT_PASSWORD`: رمز اختصاصی حداقل ۱۲ کاراکتری؛ در مخزن یا پیام‌رسان ذخیره نکنید

سپس اجرا کنید:

```sh
node scripts/create-account.js admin
```

این ابزار حساب موجود را بازنویسی نمی‌کند. برای ساخت اولین مربی با متغیرهای جداگانه:

```sh
node scripts/create-account.js coach
```

مدیر از `/admin` وارد می‌شود و می‌تواند حساب مربی/شاگرد ایجاد کند. نشست مدیر از نشست مربی و شاگرد مستقل است؛ حساب مدیر به‌عنوان مربی کلاس نمایش داده نمی‌شود. برای افزودن مدیر دیگر، ابزار سرور را با نام کاربری جدید اجرا کنید. پس از استفاده، متغیرهای موقت `ACCOUNT_*` را از محیط حذف کنید.

## امکانات

### شاگرد
- امکانات قبلی: ثبت‌نام و پروفایل، برنامهٔ تمرین، خودارزیابی، جدول پیشرفت، اطلاعیه، پشتیبانی و کارت‌های بانکی واقعی حفظ شده‌اند.
- بخش «خدمات آکادمی و امکانات جدید»: معرفی رشته‌ها، معرفی ویدیویی و افتخارات ثبت‌شدهٔ مربیان، آلبوم افتخارات ملی/استانی/بین‌المللی، مسابقات، کلاس‌ها و برنامهٔ زمانی.
- لمس یا Enter روی کارت تصویری رشته، معرفی، چهره‌های شناخته‌شدهٔ جهان و لینک جست‌وجوی آموزش پایه در یوتیوب را باز می‌کند. تصاویر نمادین‌اند، نه مدرک تمرین آکادمی. ویدیوی اختصاصی فقط پس از ثبت لینک واقعی توسط مربی نمایش داده می‌شود.
- چالش اسکوات، شنا، شکم و دو؛ نتیجه و داوری فقط توسط مربی/مدیر ثبت می‌شود. زمان کمتر در دو و تکرار بیشتر در دیگر چالش‌ها رتبهٔ بهتر دارد؛ مساوی‌ها رتبهٔ مشترک دارند.
- نتایج آزمون ماهانه و استعدادیابی و نمودار سالانه فقط از داده‌های واقعی ثبت‌شده.
- ارزیابی مربیِ کلاس خود در ماه جاری؛ یک رکورد قابل ویرایش برای هر مربی و ماه. مربی فقط میانگین و تعداد ارزیابی‌های خودش را دریافت می‌کند، نه متن یا هویت ارزیاب.
- لیدربورد هر رشته و ماه از نمرهٔ کل تأییدشدهٔ ماهانه؛ نام دیگر شاگردان برای شاگرد ناشناس است. واجدشرایط بودن برای تخفیف طبق قانون مدیر نشان داده می‌شود؛ مبلغ نهایی در صورتحساب مصوب مشخص است.
- صورتحساب و سوابق شهریهٔ خود، درخواست سفارش محصول موجود و فرم رضایت‌دار درخواست تغذیه. ثبت فرم تغذیه به معنی صدور برنامه یا توصیهٔ پزشکی نیست.

### مربی
- امکانات قبلی ثبت/ویرایش شاگرد، برنامهٔ تمرین، اطلاعیه و ثبت نمرات حفظ شده است.
- ایجاد کلاس و تخصیص شاگردان، گروه سنی/بانوان/آقایان، روز، ساعت و محل کلاس.
- ثبت نتایج ماهانه در بخش جدید با همان جدول واقعی `progress` قبلی؛ بنابراین جدول پیشرفت قدیمی، نمودار و لیدربورد همگام‌اند.
- آزمون‌های ماهانه/استعدادیابی و نتایج هر آزمون، مسابقات، افتخارات، چالش‌ها، و معرفی رشته و ویدیوی واقعی.
- دسترسی به اطلاعات ثبت‌شدهٔ شاگردان برای مسابقات و خروجی CSV؛ رمز و هش رمز هرگز نمایش داده نمی‌شود.
- مربی نمی‌تواند درخواست تغذیه، سفارش یا صورتحساب شاگرد را از API جدید بخواند. نشست «ورود به‌جای شاگرد» نیز به خدمات خصوصی آکادمی یا ارزیابی مربی دسترسی ندارد؛ ورود مستقیم شاگرد لازم است.

### مدیر
- ورود جداگانه و کنترل همهٔ بخش‌های آکادمی، حضور‌وغیاب شاگردان و مربیانِ کلاس، جلسات و صورت‌جلسه.
- تعریف تخفیف رشته/ماه/رتبه، صدور صورتحساب با محاسبهٔ مبلغ سمت سرور و تأیید دستی واریز فقط با شماره پیگیری.
- محصولات و موجودی، مشاهده و تعیین وضعیت سفارش. قیمت سفارش از قیمت ثبت‌شدهٔ محصول گرفته می‌شود؛ دادهٔ ارسالی مرورگر معتبر فرض نمی‌شود. لغو سفارش فقط یک بار موجودی را بازمی‌گرداند.
- بررسی خصوصی درخواست‌های تغذیه، بازبینی اطلاعات قدیمی و گزارش ثبت/ویرایش/حذف عملیات جدید.

## هیچ آمار ساختگی‌ای نمایش داده نمی‌شود

- دادهٔ نمونه فقط در تست‌های ایزوله با `DOJO_TEST_FIXTURES=1` مجاز است؛ حتی این گزینه در `NODE_ENV=production` نادیده گرفته می‌شود.
- اعلان‌های نمایشی خودکار و تبدیل جعلی نمرهٔ ماهانه به روزانه/هفتگی حذف شده‌اند.
- نبود نمره با صفر جایگزین نمی‌شود. نمرهٔ صفر فقط وقتی نمایش داده می‌شود که واقعاً ثبت شده باشد. میانگین فقط از مقادیر ثبت‌شده محاسبه می‌شود.
- نمودار انباشته فقط ماه‌هایی را نشان می‌دهد که چهار شاخص آن‌ها واقعاً ثبت شده‌اند؛ نمرهٔ کل تنها، همچنان در جدول، نمودار ماهانهٔ جدید و لیدربورد در دسترس است.
- قبل از اولین اجرای نسخهٔ جدید، از دیتابیس موجود نسخهٔ پشتیبان سازگار با SQLite تهیه کنید. رکوردهای قدیمیِ کاربران، نمرات، برنامه‌ها، اطلاعیه‌ها، وضعیت تمرین‌ها و خواندن اطلاعیه‌ها، فعالیت‌ها، خودارزیابی‌ها و اعلان‌ها منشأ قابل‌اعتماد ندارند؛ مهاجرت آن‌ها را **بدون حذف داده یا تغییر رمز** به `verified=0` می‌برد. از آمار و فهرست‌های عمومی خارج می‌شوند تا مدیر در «بازبینی داده‌های قدیمی» با سند واقعی تأییدشان کند. هر رکورد جداگانه تأیید می‌شود؛ تأیید کاربر، نمره‌های او را خودکار تأیید نمی‌کند.
- ورود حساب‌های قدیمی حفظ می‌شود. ادعاهای ورزشیِ تأییدنشده در نمایش پروفایل به‌عنوان واقعیت نشان داده نمی‌شوند. ویرایش معمولی پروفایل، رکورد قدیمی را خودکار تأیید نمی‌کند.

## پرداخت واقعی، نه رسید نمایشی

این نسخه **اتصال API به پرداخت‌یار، callback بانکی و تطبیق خودکار تراکنش ندارد**. تا زمانی که پرداخت‌یار و اطلاعات قرارداد مشخص نباشد، چنین موفقیتی شبیه‌سازی نمی‌شود.

`PAYMENT_PORTAL_URL` اختیاری است و باید URL امن HTTPS سامانهٔ واقعی شهریهٔ شما باشد. این تنظیم فقط لینک خروج به سامانهٔ بیرونی را فعال می‌کند، نه تأیید خودکار پرداخت. بدون این متغیر، پیام «درگاه پیکربندی نشده» نمایش داده می‌شود و شماره‌کارت‌های قبلی قابل استفاده‌اند. در هر دو حالت تأیید واریز در این نسخه دستی و با پیگیری بانکی مدیر است. سفارش فروشگاه هم «درخواست‌شده» است، نه «پرداخت‌شده».

## ذخیره‌سازی و امنیت عملیاتی

- `ARSLAN_DATA_DIR` و `ARSLAN_DB` محل دادهٔ پایدار را تعیین می‌کنند؛ هر دو فرایند باید یک دیتابیس داشته باشند. روی Railway به Volume متصل شوند. `RESET_DB` در محیط واقعی هرگز `1` نباشد.
- ورودی‌های بخش جدید allowlist، اعتبارسنجی نوع/بازه/رشته/مرجع، کنترل نقش و مالکیت و درخواست‌های تغییردهنده با هدر اختصاصی و بررسی Origin دارند. تغییر موجودی و ثبت‌های چندمرحله‌ای تراکنشی‌اند.
- محدودیت ورود مدیر، رمز هش‌شده، نشست HttpOnly/SameSite و در HTTPS کوکی Secure استفاده می‌شود. این‌ها جایگزین ممیزی امنیتی مستقل، پشتیبان‌گیری، سیاست حفظ اطلاعات پزشکی یا الزامات پرداخت واقعی نیستند.
- اطلاعات حساس را در گیت یا فایل ZIP منتشر نکنید. URL تصویر فقط HTTPS یا تصویر محلی و ویدیو فقط لینک یوتیوب می‌پذیرد. اتصال خودکار به یوتیوب/بانک یا تضمین دسترسی آن‌ها وجود ندارد.
- `npm run reset-db -- --confirm-delete` فقط برای محیط توسعه و با سرور خاموش است؛ هیچ دادهٔ نمونه‌ای بازنمی‌گرداند.

## تست‌ها (همگی با دیتابیس موقت)

```sh
npm ci
node tests/academy-migration.js
node tests/academy.js
node tests/coach-proxy.js
node tests/contact-account.js
node tests/member-details.js
node tests/port-routing.js
```

برای مرورگر واقعی، وابستگی‌ها فقط ابزار تست‌اند:

```sh
npm install --no-save --package-lock=false playwright-core@1.65.1 @sparticuz/chromium@153.0.0
BROWSER=1 node tests/academy.js
BROWSER=1 node tests/member-details.js
BROWSER=1 node tests/port-routing.js
node tests/magnifying-dock.browser.js
node tests/stacked-bars.browser.js
```

در لینوکس حداقلی ممکن است کتابخانه‌های Chromium لازم باشد. تست تولید به‌صورت جداگانه و با حساب‌های واقعی اختصاصی انجام می‌شود؛ موفقیت تست محلی به معنی در دسترس بودن دامنهٔ Railway یا اتصال درگاه نیست.
